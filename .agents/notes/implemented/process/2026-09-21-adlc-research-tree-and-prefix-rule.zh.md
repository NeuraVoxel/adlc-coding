# Agent Note: kit 新增研究树，`adlc-` 定为命名空间规则

Status: implemented

## Problem

`.agents/skills/` 里每个技能都是把某个产物推过本仓库自己的流程——spark 走 [inbox](../../../inbox/README.md)，会话进 [`learning/`](../../../learning/README.md)，版本走发版。没有一个覆盖产物出现之前的那一步：弄清事实。当维护者问某个 API 实际是什么行为、或规范允许两种方案中的哪一种时，阅读要么占着主线程，要么给出的答案没有来源记录，于是同一个问题在下次决策时被重新吵一遍。

外部有一套工程技能正好解决这件事，其中 `research` 技能的写法是"存到仓库已有放这类笔记的地方"。但本仓库没有这样一个开放位置：每个候选落点都带[门禁](../../README.md)——Agent Note 强制 header 与骨架，`docs/` 实行双语配对且面向采用者——因此照搬该技能，要么撞门禁，要么把证据当成决策归档。它的 `agents/openai.yaml` 是第二个问题：本仓库没有任何技能带这个文件，收下它就等于引入一个只有单个成员的约定。

## Decision

`.agents/research/` 是 `inbox/`、`learning/` 之外的第四棵工作树，存放研究笔记：一个问题、其结论、以及每条结论的来源。它的 [README](../../../research/README.md) 与两个邻居共用同一套四段式合同——边界、条目语言、布局、生命周期——条目默认中文，命名 `yyyy-mm-dd-slug.md`，并规定没有来源的结论不属于本目录。

与最近邻的边界是**方向性**的，这点最值得记住：[`learning/`](../../../learning/README.md) 反思的是**本仓库、本次会话**；`research/` 报告的是从**外部**取得的证据，主题不归本仓库所有——笔记之所以存在，就是因为有结论需要来源。与学习笔记一样，研究笔记在持久事实进入 Agent Note 或已发布文档后被"吸收即删除"，绝不成为第二套权威。

迁入的技能是 [adlc-research](../../../skills/adlc-research/SKILL.md)。它派一个后台 agent 去读一手来源、主线程继续干活；在**派发之前**先定死输出路径，使运行中的 agent 无法覆盖已有笔记；并把"没有找到归属来源的结论"视为不构成结论。上游有两处被丢弃：`agents/openai.yaml`，理由即上述"单成员约定"；以及"存到仓库已有放这类笔记的地方"这一句，代之以钉死的 `.agents/research/` 路径。后一处丢弃的代价是丧失对未采用本布局的仓库的可移植性——这是有意为之，因为在本仓库内每个替代落点都带门禁。

本次变更的另一半是前缀规则。`adlc-` 现在标识"本 kit 自己的技能命名空间"——即"由本 kit 发布"——而不再是"操作 `.agents/` 目录树"。不做这层放宽，一个通用工程技能就无法在不引入第二套命名方案的前提下加入这个家族，且后续每个上游技能（tdd、code-review、diagnosing-bugs……）都会在迁移时重开同一个问题。因此 `.agents/skills/` 下的每个技能都带前缀。

登记沿用既有打包规则，不另发明：三个新文件加入 installer 的 `workflows` 组件（[`lib.ts`](../../../../packages/create-adlc-coding/lib.ts)）；README 对加入 [`verify-doc-pairing`](../../../../scripts/verify-doc-pairing.ts) 的 `pairedRootFiles`，使新树与其邻居一样受双语门禁约束；目录表与 installer 组件表都登记这棵新树。

## Alternatives considered

- **把研究笔记放进 `.agents/learning/`。** 落选：两棵树回答的是相反的问题——对本仓库的反思 vs 对外部主题的取证——一棵树会承载两套生命周期，且以后无法在不搬文件的情况下补上这条边界。
- **作为 Agent Note 放进 `.agents/notes/proposed/`。** 落选：Agent Note 即决策，其格式门禁要求 header 与骨架；而多数调研是给尚未做出的决策提供证据，硬套格式只会产出空决策或让门禁说谎。研究在被吸收时才成为 Agent Note，而不是在被采集时。
- **把笔记钉进 `docs/`。** 落选：`docs/` 实行双语配对、陈述面向采用者的合同，而研究笔记是单语工作笔记，多数会过期。
- **不加技能，继续在主线程里现读。** 落选：这正是 Problem 描述的现状——阅读占着主线程，无来源的答案被反复吵。
- **照搬上游技能，让它自己挑落点。** 落选：它依赖本仓库并不存在的约定，而每个候选落点都带门禁，于是"挑个合适的"实际是猜，且会在以后响得很大声。
- **新建一个 `research` installer 组件，而不是扩展 `workflows`。** 落选：`AGENTS.md` 会链到这棵树，而 installer 的 spec 从这些链接反推必需组件，因此新建组件会连带改动 `COMPONENT_REQUIRES` 与守护它的 spec——相较于"已经承载了 `AGENTS.md` 所指其他全部合同的那个组件"，没有任何收益。
- **保留旧的前缀含义，把这个技能就叫 `research`。** 落选：家族将运行在两套命名方案上，`workflows` 组件会承载一份混杂的目录，且以后每次迁移都要重吵；前缀真正的职责是标识 kit 归属，一次放宽比为每次迁移重决更便宜。
- **保留 `agents/openai.yaml`。** 落选：那是面向 Codex 的元数据，而本仓库并未配置该 harness 的任何策略；孤零零一个文件就是待发生的漂移。

## Consequences

有外部答案的问题现在有了决策可引用的落点，阅读也不再占用主线程。三棵工作树位于 notes 树之外，它们之间的边界是一条写下来的方向性规则——`notes/` 做决策、`learning/` 向内反思、`research/` 向内报告外部事实——而非会随时间腐烂的默契。

`adlc-` 被记录为 kit 的命名空间，此后迁移其余上游技能无需重决此事。被迁入的技能本身不再可移植到未采用本布局的仓库；这份代价限于其落点条款而非其方法，方法仍与上游所写的一样可复用。
